## Context

使用者可能只知道手里的开发板型号，并不知道交叉编译、目标变体、刷写镜像或工作区的含义。
现有开发指南偏参考手册，Wiki 保留多套旧实现描述。此次只调整文档信息架构和事实表达。

## Goals / Non-Goals

**Goals:** 新读者能选择起点、完成一次有明确结果的操作，并知道继续使用、维护或扩展应读哪里。

**Non-Goals:** 不凭模拟阅读声称真人可用性测试完成，不新增运行时功能，不编造硬件接线与验证结果。

## Decisions

- README 负责定位与分流；first-steps 逐步教学；development-guide 提供完整操作参考。
- maintenance-guide 解释从问题到源码、验证和提交的闭环；extension-guide 按 App、产品、Package、板卡、平台逐层引导。
- 每条入门路径说明在哪里运行、需要什么、将改变什么、成功时看到什么和下一步；板卡示例明确不能套用到任意设备。
- 图示选择 GitHub 原生 Mermaid 与目录树，文字紧邻解释同一关系；保持标注可读，不靠颜色传递唯一含义。
- Wiki 侧重硬件与专题知识。与当前架构重复的页面给出简明概念及权威入口，历史记录保留日期和适用范围。
- 用新工作区运行文档中的只读与脚手架命令，用当前解析器核验配置示例，并检查链接与图示语法。

## Risks / Trade-offs

- 增加入门页可能重复细节 → 只解释首次成功必需概念，将完整字段及平台规则链接至单一参考页。
- 简化文案可能掩盖硬件前提 → 将软件计划、编译成功、设备启动和功能验收分别说明。
- Wiki 历史信息可能被误删 → 保留硬件事实与历史记录，明确修订当前导航、命令及已证实失效的架构描述。
