## Context

当前 `builder/term.py` 已提供终端能力与文本宽度工具，`BuildOutput`、刷写控制台和目标选择器仍各自维护样式。公共命令有结构化结果，能够区分缓存可复用、待构建、执行失败与用户取消，但呈现层尚未把这些状态统一映射为颜色。

本变更遵循 `ProjectSpec.md` 第 14 节：构建保持分层输出、真实状态与纯文本日志，所有新增颜色都只是已有事实的辅助表达。已有未提交变更保持原样，颜色改动不进入构建配置、指纹或产物清单。

## Goals / Non-Goals

**目标：**

- 为公共 CLI（命令行界面）、构建、刷写和目标选择建立单一语义颜色来源。
- 按已知业务状态呈现颜色，使可复用、需构建、待准备、失败与取消可辨。
- 在管道、重定向、禁用颜色和低能力终端中保留同样的文字含义。
- 保持 JSON、日志、退出码与执行行为稳定。

**非目标：**

- 不添加主题配置、强制彩色开关或终端框架依赖。
- 不修改命令布局、构建进度、缓存判断或设备操作。
- 不对任意工具输出做新的关键词着色，不改变既有失败上下文提取。

## Decisions

### 1. 语义角色是唯一颜色来源

`builder/term.py` 提供 `Role` 枚举与 `style(text, role, *, stream=None)`。调用方表达内容的语义角色，由终端层决定样式；构建、刷写和目标选择删除重复调色板。

`envsetup.sh` 的 TTY 就绪提示调用 Python 呈现层的 `presentation.render_ready()`，复用同一颜色定义，Shell 不维护 ANSI 配色。非 TTY 继续不输出就绪提示，也不改变调用者的命令跟踪状态；`cli-envsetup` 的既有行为契约保持不变。

| 语义角色 | 样式 | 典型内容 |
|---|---|---|
| 标题、正常需构建、进行中 | 蓝色；标题加粗 | 任务名称、需构建、正在构建、正在刷写 |
| 成功、可复用 | 绿色 | 构建完成、检查通过、缓存可复用 |
| 警告、受阻待准备、取消 | 黄色 | 缺失前置条件、待准备、用户取消 |
| 错误、失败 | 红色；错误可加粗 | 构建失败、无效配置、失败步骤 |
| 路径、命令 | 青色 | 产物位置、日志位置、下一步命令 |
| 正文 | 终端默认前景 | 名称、说明、结构化字段值 |
| 次要说明 | 默认前景并降低亮度 | 耗时、辅助标签、详细工具输出前缀 |

保留终端默认前景可适应浅色和深色主题；基础终端色减少对特定调色板的依赖。替代方案是在各模块直接指定颜色，但它会继续允许同一状态出现不同颜色，也无法集中验证降级行为。

### 2. 呈现层根据状态选择角色

公共命令在读取结果字段时显式选择角色，状态值、执行结果和错误类型是颜色依据。`why` 的缓存可复用为绿色成功语义；正常缓存未命中（`status=miss`）表示有工作待执行，采用 `Role.ACTIVE` 的蓝色语义，不属于警告或失败。输入未准备、尚不能判断执行条件（`status=blocked`）采用黄色待准备语义。用户取消也采用黄色，并保留“取消”文字与退出码 130。

状态符号和文字继续存在，例如 `✓`、`✗`、`⊘`、可复用、需构建和取消。只在局部状态、标题、路径和命令着色，正文保持默认前景。替代方案是对拼接后的整段输出匹配“成功”“失败”等文字；它会把路径、错误上下文或“未失败”等内容误判为业务状态，因此不采用。

### 3. 使用实际输出流动态检测能力

样式函数在每次调用时检查实际输出流是否为 TTY（交互终端），以及 `NO_COLOR` 是否存在（空值也禁用）、`TERM=dumb` 和既有 `--no-color` 设置。不得在模块导入时冻结 stdout/stderr 能力，避免测试替换流或命令重定向后继续输出颜色。

stdout 与 stderr 分别判断，保证“结果重定向到文件、诊断仍在终端”等组合可靠。无颜色环境中，普通命令禁用动画和进度重绘；交互式目标菜单保留必要的导航绘制与焦点反显，非 TTY 不进入菜单。JSON 序列化使用原始结果数据；JSON 模式在本次调用期间临时设置 `NO_COLOR=1` 并在结束后恢复环境，保证 stderr 中的过程也不添色。持久化日志只接收或保留去除控制码后的原文。

### 4. 用行为断言验证语义与降级

测试覆盖有能力的 TTY、非 TTY、`TERM=dumb`、空值与非空 `NO_COLOR`、独立 stdout/stderr 以及动态替换输出流。公共命令用构造的真实结果覆盖成功、待构建、失败、取消与路径命令，并验证 JSON 模式过程保持纯文本；构建和刷写继续验证日志不含控制码。环境初始化沿用 Shell 行为回归测试。此变更只影响呈现层，不需要执行系统编译或设备刷写来证明颜色契约。

## Risks / Trade-offs

- [终端配色影响实际色相和对比度] → 使用基础终端色与默认前景，并始终保留状态文字和符号。
- [调用方对正常待构建与故障作出错误分类] → 在呈现分支读取明确状态，对缓存未命中和取消添加回归用例。
- [颜色进入机器输出或日志] → JSON 保持原始数据，日志继续去除控制码，并独立验证重定向与日志文件。
- [迁移影响菜单焦点和构建活动行] → 保留既有布局与重绘机制，只替换样式来源，验证禁色和窄终端行为。

## Migration Plan

1. 增加共享角色与样式接口及能力测试。
2. 迁移公共 CLI、构建、刷写和目标选择，并保留文本结构与输出协议。
3. 同步规范和指南，运行定向测试与 OpenSpec 校验。
4. 验证完成后由本次主任务更新任务状态；归档另行执行。回退仅需撤销本变更的呈现层与文档改动，不涉及数据迁移。
