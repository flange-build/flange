## Context

本次范围是设计评审与文档交付。源码已包含近期缓存、平台共享和资源优先命令重构，旧路线图不能代表现状。
工作区还有用户未提交的源码修改，所有审查以当前工作区为准，记录验证限制。

## Goals / Non-Goals

**目标：** 读者可从公开仓库完成首构建，理解 App 迭代流程、模块职责和现存缺口；维护者可按证据规划优化。

**非目标：** 本次不实现报告提出的新工作区、SDK（软件开发工具包）、并行调度或设备测试框架。

## Decisions

1. README 提供定位、快速开始、外部 App 示例、支持矩阵和导航；完整操作进入开发指南，职责与约束进入 ProjectSpec。
   不继续将所有平台操作和内部原理堆在首页，以减少同一事实的重复维护点。
2. 架构说明只描述实际代码；评审报告单独记录目标架构、缺陷证据及每项不超过两小时的工作单元。
   历史 HTML 与路线图保留可追溯性，入口显式提示历史地位。
3. Logo 作为仓库本地资源提交，保留既有资源，使用新文件名；不依赖外部托管图片。
4. README 不使用未经测量的性能比较、全平台验收承诺或虚构通过状态徽章。
   采用用户最终指定的 Apache-2.0，标准 LICENSE 使用官方原文，第三方内容保留上游许可。
5. 通过 CLI 帮助、配置求值、现有测试、相对链接和资源渲染校验文档；硬件相关步骤仅验证接口。

## Risks / Trade-offs

- 文档数量多且历史材料广泛：先建立当前文档入口和事实源，详细列出仍需自动化同步的范围。
- 模拟测试不能代替 Docker 编译和设备启动：报告明确测试层级，后续以代表板实机矩阵验收。
- 本地基线可能已有失败：区分既有失败与本次文档变更，不修改测试来隐藏失败。

## Migration Plan

先保存提案，再更新当前入口文档与评审，完成校验后归档此文档变更。
运行时行为不变，回退只需撤销本次文档与新资源。

## Open Questions

架构实施顺序以评审的依赖关系和实机资源为输入；全仓第三方材料清单尚待后续审计。
