## Why

flange 已具备组件增量构建与 App/Package 生命周期入口，但公开文档仍混用历史配置语法、目录和能力承诺。
开源前需要基于当前代码审查第一性原理与维护边界，让首次使用者和维护者获得同一套可验证的事实。

## What Changes

- 输出覆盖构建、配置、外部开发、验证调试与发布的设计评审，附源码证据、优先级和分阶段验收任务。
- 重写 README，加入仓库内 Logo、真实快速开始、能力边界、文档导航、贡献和许可状态。
- 补齐从 clone 到构建、刷写、App 开发和排障的指南，更新架构说明与 ProjectSpec 的当前行为描述。
- 将历史设计与路线图明确标为历史材料，避免把已完成优化再次列为待实现。
- 按用户最终选择加入 Apache License 2.0，并同步 Python 包许可元数据及第三方许可边界说明。

## Capabilities

### New Capabilities

- `developer-documentation`: 面向用户与维护者的分层文档、生命周期指南、能力状态和设计评审证据约定。

### Modified Capabilities

无。本次不改变构建和部署 API（应用程序接口）的运行行为。

## Impact

涉及 README、ProjectSpec、docs 文档、品牌资源、LICENSE 与 pyproject 许可元数据；不引入运行依赖，不改变设备状态。
后续架构建议单独评估与实施，本次评审不将其表述为已实现功能。

## 非目标

- 不在一次 review 中重写构建引擎或引入新的工作区、调度器、SDK 协议。
- 不运行全系统编译或真实设备刷写，不代替实机验收。
- 不变更第三方内容的上游许可证，不覆盖当前工作区已有源码改动。
