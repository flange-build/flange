## Why

当前构建缓存同时存在“无变更仍重建”和“输入已变更却命中”两类错误：跟踪 branch 的源码、仓库内 vendor 包会被无条件判为未命中，而部分板级配置、共享库和构建逻辑又没有进入内容哈希。最近一次 `radxa-dragon-q8b-default-debug` 构建因此耗时约 17 分钟，其中 kernel 与 rootfs 被重复构建，已经直接削弱增量构建的核心价值。

## What Changes

- 在缓存判定前解析并同步源码身份，使 branch 在提交未变化时可以命中缓存。
- 修复构建后仍写入判定前旧哈希的问题，保证缓存记录对应实际参与构建的源码。
- 区分仓库内受控的本地包与真正的外部本地源码；前者按内容缓存，后者继续保留本地增量构建语义。
- 补齐影响各组件产物的配置、源码、共享库与构建逻辑输入，并补全动态产物门禁。
- 强化 rootfs 下载与分阶段缓存的输入完整性，避免下载中断或软件源变化复用错误缓存。
- 增加覆盖命中、失效传播和缺失产物的最小回归测试。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `build-cache`：修正源码身份解析时序、内容哈希输入、缓存写入时机、rootfs 分阶段缓存及产物完整性门禁。

## Impact

- 主要影响 `builder/cache.py`、`builder/engine.py`、`builder/source.py` 及相关测试。
- 首次运行会因哈希契约升级而重新构建受影响组件；之后无变更构建应直接命中。
- 不改变 `flange build` 或 `flange flash` 命令接口；自定义 rootfs 来源需补充
  `rootfs.sha256`，stock 配置随变更一并迁移。

## 非目标

- 不实现远程共享缓存、分布式构建或跨主机缓存迁移。
- 不替换组件自身的 Make、ccache 等增量机制。
- 不为缓存系统引入新的第三方依赖或独立服务。
