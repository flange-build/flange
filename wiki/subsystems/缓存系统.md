## TL;DR

`BuildCache` 以内容哈希为键，管理组件级（`is_up_to_date`/`store`）和阶段级（`is_phase_up_to_date`/`store_phase`）两层缓存；哈希覆盖源码树、config、分区表、补丁、固件等所有影响产物的因素。

## 关键设计要点

- **组件级缓存**：`is_up_to_date` 比较 `compute_hash(component)` 与 `.build/cache/<component>.hash`，相同且产物齐全则跳过构建；`store` 在构建完成后写入哈希文件
- **阶段级缓存**：`compute_phase_hash` / `is_phase_up_to_date` / `store_phase` 供 rootfs 两阶段（base 和 customize）独立缓存；Phase1 结果可在 Phase2 变更时复用
- **目录递归哈希**：`_hash_directory` 对目录内文件按路径排序后 SHA256 递归混入，产出稳定哈希
- **Source tree 混入**：`_mix_source_tree` 优先用 `.git/HEAD`（即 commit SHA）快速哈希；无 git 则降级到 `_hash_directory` 全扫
- **分区表混入**：`_mix_partitions` 将 config 中分区大小/类型/顺序串行化后混入，分区变更触发 image 重建
- **排除规则**：`_hash_directory` 跳过 `__pycache__`、`.pyc`、`.git` 等，避免无关文件污染哈希
