# 缓存系统

`BuildCache(context=...)` 是 TaskPlan（任务计划）到 ArtifactManifest（产物清单）的系统缓存边界。
概念入门见[内容哈希与增量构建](../concepts/内容哈希与增量构建.md)。

| 当前接口 | 职责 |
| --- | --- |
| `load(task_id)` | 读取 `<target_dir>/<task_id>/manifest.json` 的有效格式记录 |
| `dependency_identities(plan, manifests)` | 验证上游产物，并取得实际产物身份 |
| `explain(plan, manifests)` | 返回命中、缺失、禁用或阻塞状态，以及具名输入变化原因 |
| `is_up_to_date(plan, manifests)` | 输入、必需输出声明及实际文件均校验成功才命中 |
| `store(plan, before, manifests, ...)` | 比较执行前后指纹，捕获完整产物并原子写入成功记录 |

`load()` 得到可解析清单不等于本次命中；必须继续校验输入和产物。
文件损坏、权限变化、输出类型不符、必需产物缺失、依赖失效都会阻止复用。
旧 `.build_hash`、`<component>.hash` 和阶段哈希文件不再是当前协议。

文件树摘要属于 [`digest.py`](../../builder/digest.py)，计划属于
[`graph.py`](../../builder/graph.py)，产物捕获与验证属于
[`artifacts.py`](../../builder/artifacts.py)。
rootfs 基础快照单独由 `rootfs_base.py` 与 `snapshot.py` 管理，见
[rootfs 两阶段缓存](../concepts/rootfs-两阶段缓存.md)。

排障先运行 `flange why <component>`。修改缓存声明时，同时检查真正执行者是否消费同一输入，
并验证失败不会留下可误用的成功记录；完整流程见[维护指南](../../docs/maintenance-guide.md)。
