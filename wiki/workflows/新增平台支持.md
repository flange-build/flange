## TL;DR

创建 `components/platform/<vendor>/`（数据）+ `builder/platforms/<vendor>/`（逻辑），两者严格分离，不改框架核心。

## 目录结构

```
components/platform/<vendor>/   # 数据：patches、u-boot config 等
builder/platforms/<vendor>/     # 逻辑：Python Builder 子类
  ├── kernel.py / bootloader.py / rootfs.py / image.py
  └── recovery.py / boot.py（按需）
```

## 必须实现

**Builder 子类**：各实现 `build()` 方法，读取 [[FINAL_CONFIG]] 平台字段，在 Docker 内执行编译/打包。

**FlashStrategy 子类**（`builder/flash.py`）：实现 `generate_pre_flash_config` 和 `flash`，注册到 `_FLASH_STRATEGIES`（L356）。

## 配置 schema 对齐

新平台的 board config.py 需能通过 `platform` 字段路由到对应的 Builder 和 FlashStrategy；确保 `partition`、`flash_tool`、`boot` 等字段 schema 与框架期望对齐。

- [[rockchip 平台]]：完整实现，可作为参照基线
- [[allwinnera733 平台]]：进行中，涵盖 SD 卡 raw 镜像模式与 recovery 分区适配（commit 33bc2c2）
