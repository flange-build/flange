# 新增平台支持

新平台需要把配置能力、构建配方、产物和宿主刷写接成一条可验证链。
`components/platform/<vendor>/` 保存配置与补丁，`builder/platforms/<vendor>/` 保存 Python 策略。
仅创建这两个目录不能证明该平台已具备完整生命周期。

| 需要连接的边界 | 检查方向 |
| --- | --- |
| 配置与能力 | `platforms/spec.py` 的显式能力注册、严格 schema 与有效组合 |
| 构建计划 | 组件启用状态、输入、依赖、必需产物与平台工厂 |
| 平台配方 | 复用 ComponentBuilder，共享逻辑中只保留可通用机制 |
| 镜像与刷写 | 分区解析、FlashPlan 构建期数据、FlashStrategy 宿主执行 |
| 验证记录 | 配置测试、真实容器产物、设备启动及介质/外设验收分别记录 |

完整实施步骤和代码修改落点见[扩展指南](../../docs/extension-guide.md)，
边界说明见[构建系统设计](../../docs/build-system-design.md)。
[FlashStrategy](../concepts/FlashStrategy-抽象.md) 与[平台索引](../platforms/index.md)
可帮助比较现有启动/刷写路径；不要仅根据 vendor 名称猜能力。
