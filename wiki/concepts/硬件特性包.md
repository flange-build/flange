## TL;DR

硬件特性包（`components/packages/<pkg>/`）把「一组配套的内核驱动 + 设备树 overlay + 固件」收敛成自描述单元，board 通过 `packages: [...]` 一行 opt-in 即可启用。`package.py` 清单声明若干 component，每个带 `type`，构建引擎按 type 分发到既有流水线，包机制本身只是薄胶水层。

## 关键设计要点

- **清单**：`package.py` 导出 `PACKAGE = {"name", "components": [...]}`，`name` 必须与目录名一致。component `type` ∈ `oot-driver` / `devicetree` / `deb`。
- **opt-in**：board 顶层 `packages` 字段，项可为字符串（整包默认集）或 dict（`{name, drivers: [...]}` 按需选子集）。
- **类型分发**（`expand_hardware_packages` 在 `resolve_config` 末尾注入 config）：
  - `oot-driver` → 合成 `kernel.oot_modules` 条目（绝对路径 + `{arch}/{cross_compile}/{kernel_src_abs}` 模板），复用 [[out-of-tree 模块]] 编译/安装。
  - `devicetree` → 注入 `boot.package_overlays` + `boot.package_overlay_sources`，作为 overlay 第四源由 device-tree-overlay 组件 cpp+dtc 编译（见 [[双 extlinux 配置]]）。
  - `deb` → 预留。
- **按需编译**：未被选中的 oot-driver 不编译、不装 `.ko`。
- **增量**：`packages_meta.{kernel_src_paths, overlay_src_paths}` 把包源内容混入 kernel / device-tree-overlay 内容哈希。

## 实例

- **meizu-e3-panel**（魅族 E3 MIPI-DSI 屏）：`sec_ts` 触摸 + `sgm37604a` I2C 背光两个 oot-driver + 按 board 路由的 panel `.dtso`。
  - rock5b（RK3588）：`rk3588-rock-5b-meizu-e3-panel.dtso`，Rockchip DRM 栈。已实机点亮。
  - **跨 SoC 复用范例** [[radxa-cubie-a7a]]（A733）：`sun60i-a733-cubie-a7a-meizu-e3-panel.dtso`。同包 opt-in `[sec_ts, sgm37604a]`，panel overlay 按 Allwinner sunxi 栈（`allwinner,panel-dsi` + virtual-panel OF-graph）重写；OOT 驱动业务逻辑不变，仅补两处 6.1→5.15 跨内核兼容垫片（`<linux/wakelock.h>` 缺失用 `__has_include` 回退 wakeup_source、i2c `.remove` 返回类型用 `LINUX_VERSION_CODE` 守卫）——印证「devicetree component 按 board 路由、oot-driver 跨 SoC 复用但需版本守卫吸收内核 API 差异」的分层。

## 易踩坑

- 老 BSP U-Boot（rock5b 为 2017.09）libfdt `overlay_symbol_update` 要求 overlay 内 label 符号为 `/fragment@N/__overlay__/...`：**新增根级节点必须包进显式 `fragment target-path="/"`**，否则根相对符号致 `FDT_ERR_BADOVERLAY`、boot 挂死。
- panel 与 dsi 间需 OF-graph 端口（`drm_of_find_panel_or_bridge(port=1)`），否则 `-19 找不到 panel`。
