# 硬件特性包

Package（硬件特性包）把配套驱动、设备树 overlay（覆盖）和 vendor App（配套应用）组织成自描述单元。
先理解[App 构建](../components/app-打包系统.md)与[配置组合](三层继承.md)，
实施步骤见[扩展指南](../../docs/extension-guide.md)，完整字段与动作语义见[App 架构](../../docs/app-architecture.md)。

| component.type | 系统集成方向 |
| --- | --- |
| `oot-driver` | 展开为内核树外模块，在 kernel 组件编译与安装 |
| `devicetree` | 展开运行期 overlay 的 Package 来源；构建期 DTB 合并另有配置 |
| `vendor` | 引用包内 App，复用 AppBuilder、DebBuilder 与 App 生命周期 |

`package.py` 导出 `PACKAGE`；顶层允许 name、description、components、actions。
board 通过 `packages` 显式启用全部驱动或选择驱动子集，未选择的驱动不编译、不安装。
派生的 `packages_meta` 和 overlay 来源属于解析器输出，不能由作者作为最终字段手工注入。

仓库外开发也必须位于工作区；先执行 `flange init`，再选择目标：

```bash
flange package create demo --dir packages --type exec --build-system cmake
flange package plan ./packages/demo
flange package build ./packages/demo
```

默认独立流程委托 vendor App；多个 vendor 运行或调试时使用 `--component` 选定对象。
驱动与设备树通过系统计划集成，不能从 Package 的独立部署命令推断会自动刷写分区。
Package 路径模式不修改 board 配置，也不隐式加载包内 `config.jsonnet`。

vendor App 产物归属当前工作区 `<target_dir>/apps/<resource-id>/`。
显式 `actions.build` 在 Docker 隔离副本执行，将专属结果写到 `FLANGE_PACKAGE_OUTPUT_DIR`
（同 `FLANGE_TARGET_DIR`），成功后发布到 `<target_dir>/packages/<resource-id>/` 并产生 manifest。
后续显式动作消费验证后的同一清单，因此只有 actions 或混合 component 的包也能有明确产物契约。

`actions` 支持 `build/deploy/run/debug/log/test` 的非空 argv（参数向量）列表。
非 build 动作在宿主执行，显式动作不要求先选择 ADB，可自行使用其他传输。
`package.py` 是加载时执行的 Python；清单严格校验不等于对其中代码做沙箱隔离。
具体参数、设备会话与错误处理统一查[开发指南](../../docs/development-guide.md)。

下方保留具体板卡的历史适配实例；内核 API、接线和验收结论只适用于各段说明的基线。

## 实例

- **meizu-e3-panel**（魅族 E3 MIPI-DSI 屏）：按 SoC 显示栈选 panel 驱动与背光驱动，按需 opt-in：
  - rock5b（RK3588，Rockchip BSP）：`simple-panel-dsi` 驱屏 + 板载 `pwm-backlight`；opt-in `[sec_ts]`，不取 sgm37604a。
  - [[radxa-cubie-a7a]]（A733，Allwinner BSP）：`allwinner,panel-dsi` 驱屏 + 屏自带 SGM37604A I2C 背光；opt-in `[sec_ts, sgm37604a]`，仅补两处 6.1→5.15 跨内核兼容垫片（`<linux/wakelock.h>` 缺失用 `__has_include` 回退 wakeup_source、i2c `.remove` 返回类型用 `LINUX_VERSION_CODE` 守卫）。
  - [[radxa-dragon-q6a]]（QCS6490，mainline drm/msm）：QCLINUX BSP 6.6.90 的 `drivers/gpu/drm/panel/` 是纯 mainline 风格，91 个驱动一型一驱、**没有**通用 DSI panel driver。包内随之新增第 3 个 oot-driver `panel_meizu_e3`（drm_panel 风格 ~250 行）+ SGM37604A I2C 背光（与 a7a 同款）；overlay 经 [[构建期 dtb overlay 合并]] 合到 base dtb（grub-with-dtb 无运行时 overlay）。opt-in `[sec_ts, sgm37604a, panel_meizu_e3]`。

> 印证 **devicetree component 按 board 路由 / oot-driver 跨 SoC 共享但按需 opt-in / 内核 API 差异由跨版本守卫吸收 / 缺通用驱动时包内补 OOT** 的分层模型。

## 易踩坑

- 老 BSP U-Boot（rock5b 为 2017.09）libfdt `overlay_symbol_update` 要求 overlay 内 label 符号为 `/fragment@N/__overlay__/...`：**新增根级节点必须包进显式 `fragment target-path="/"`**，否则根相对符号致 `FDT_ERR_BADOVERLAY`、boot 挂死。
- panel 与 dsi 间需 OF-graph 端口（`drm_of_find_panel_or_bridge(port=1)`），否则 `-19 找不到 panel`。
