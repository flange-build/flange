# 架构总览

flange 把板卡配置、源码和软件包转换为可刷写的嵌入式 Linux 系统，并提供独立 App（应用）开发路径。
它复用 ubuntu-base 与发行版软件包；性能与可重复性要结合实际输入和环境验证。

第一次使用先读[初学指南](../../docs/first-steps.md)。本页解释各部分如何连接，
完整维护边界见[构建系统设计](../../docs/build-system-design.md)。

```mermaid
flowchart LR
  User[宿主 Python CLI] --> WS[工作区与目标]
  WS --> Config[Jsonnet 求值与严格校验]
  Config --> Plan[TaskPlan 输入与依赖计划]
  Plan --> Docker[Docker 编译与镜像制作]
  Docker --> Manifest[已验证产物与清单]
  Manifest --> Flash[宿主刷写或 App 部署]
  Flash --> Board[目标设备]
  Board --> Evidence[运行 / 测试 / 调试记录]
```

| 概念 | 回答的问题 | 入口 |
| --- | --- | --- |
| WorkspaceContext（工作区上下文） | 工具、项目和输出各在哪里？ | [仓库与工作区](仓库三层结构.md) |
| Target（构建目标） | 为哪块板、哪个产品和变体构建？ | [product / variant](product-variant.md) |
| FINAL_CONFIG（最终配置） | 当前目标实际启用了什么？ | [配置事实源](FINAL_CONFIG.md) |
| TaskPlan（任务计划） | 依赖、输入和必需产物是什么？ | [构建引擎](../subsystems/构建引擎-BuildEngine.md) |
| ArtifactManifest（产物清单） | 文件是否确实属于一次有效成功构建？ | [内容哈希与增量构建](内容哈希与增量构建.md) |

宿主负责 CLI、工作区与容器编排、USB/ADB 设备操作；Docker 负责目标代码编译、chroot 与镜像制作。
平台 Python 策略位于 `builder/platforms/`，硬件配置、补丁和覆盖文件位于 `components/`。
具体启动链和刷写工具随平台不同，见[平台索引](../platforms/index.md)，不可套用同一份线刷步骤。
