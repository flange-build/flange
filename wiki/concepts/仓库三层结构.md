# 仓库三层结构与工作区

“代码 / 内容 / 产物”描述的是职责；使用外部工作区时，它们可以分布在不同目录。
先读[架构总览](架构总览.md)，操作见[开发指南](../../docs/development-guide.md)。

| 层 | 位置 | 应放入的内容 |
| --- | --- | --- |
| 框架代码 | `<tool_root>/builder/` | CLI、配置校验、构建引擎和平台策略 |
| 版本控制内容 | `<tool_root>/components/` | board/SoC/platform 配置、App、Package、补丁、overlay |
| 可再生成产物 | `<build_root>/` | 下载缓存、隔离工作树、发布文件和日志 |

`flange init` 创建的 `flange.toml` 指定工具根、输出根和外部 App 来源。
工具 checkout（工作副本）自身也可作为工作区。默认 `build_root` 是当前工作区 `.build`，
可通过清单的 `build_dir` 改到另一个目录；`flange status` 显示实际路径。

```text
<workspace_root>/flange.toml
<workspace_root>/.flange/current_config       # 当前工作区的目标选择
<build_root>/sources/                        # 共享下载与源码存储
<build_root>/work/<target.key>/              # 目标独立的可变工作目录
<build_root>/target/<board>/<product>/<variant>/  # 已发布结果
<build_root>/cache/rootfs-base/               # 基础 rootfs 快照
<build_root>/locks/                          # 构建并发锁
```

`builder/paths.py` 集中定义目录名与工具仓库默认锚点；实际运行路径从
[WorkspaceContext](../subsystems/路径锚点-paths.md) 派生。新代码不能用全局 `BUILD_ROOT`
代替调用者工作区的输出根，也不应依赖旧根目录 `target` 软链接；当前初始化不会创建该链接。

内核源码与实际构建工作树要求大小写敏感文件系统。macOS 默认 APFS 通常不满足，
应按[开发指南](../../docs/development-guide.md)选择 APFS Case-sensitive 输出卷。
